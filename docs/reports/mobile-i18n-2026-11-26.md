# Mobile English / Chinese delivery — 2026-11-26

## Scope and behavior

RecDock Mobile source version is `0.3.1+4`. Android and iOS support English and Simplified Chinese. The first launch defaults to English independently of system language. **Settings → Interface language** switches the interface without restarting; the choice is saved per installation, independently of the account and transcription-language settings.

The shared Flutter interface covers the library, account/login, device discovery/status/download, transcription configuration, explicit cloud-upload consent, background task notices, revision review, speaker labels, and full export. Existing authored task notices are translated when displayed, without migrating or rewriting task journals.

Recording titles, transcript text, custom speaker names, source hashes, JSON export data, and transcription settings retain their original content. Default speaker labels are translated only when their `nameSource` is `default`. Interpolation inserts arguments in one pass, so text such as `{1}` inside a title remains literal.

Android notifications and share-sheet labels read the same non-secret preference as Flutter. Running foreground-service notifications refresh after a language change. iOS completion notifications use localized bundles selected by the saved app preference. System-owned dialogs follow the operating system language; both English and Chinese Bluetooth purpose strings are included in the iOS bundle.

The empty-library presentation now scrolls when large text or a small viewport requires it. No recording storage schema, authentication protocol, cloud submission policy, or transcription model was changed.

## Distribution

Release: [Mobile 0.3.1 preview 1](https://github.com/audiobridge-ai/recdock/releases/tag/mobile-v0.3.1-preview.1). This is separate from the desktop release channel.

The [mobile workflow](../../.github/workflows/mobile.yml) runs analysis, tests, release-mode Android compilation, and unsigned iOS Simulator compilation. Mobile tag releases require both jobs to pass and publish an Android APK, `build-info.json`, and `SHA256SUMS.txt`. Source commits and artifact digests are recorded in the manifest.

The Android preview uses the existing debug signing configuration. It is an experimental sideloadable APK; signature compatibility between CI builds is not guaranteed. Back up important data before replacing a test installation. No production signing key was created or committed.

No installable iOS IPA is published: distribution signing/provisioning has not been configured. Physical-iPhone installation needs an authorized signing workflow or future TestFlight/App Store delivery. No company signing credentials were used.

The Mac release and website downloads remain unchanged. The mobile app still uses the user's AssemblyAI cloud transcription key and explicit upload consent; it does not adopt the Mac app's local-model workflow. Live PLAUD hardware/account regression and physical-iPhone acceptance remain outside this language-only delivery.
