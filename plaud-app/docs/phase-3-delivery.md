# 第三阶段交付：纯客户端后台转写

版本 0.3.0+3。根据用户希望不引入公网服务、APNs/FCM 的要求，实现本机任务调度；AssemblyAI Key 继续自带。

## 已完成

- FIFO 持久队列，逐条上传，最多两条未确认结束的云端任务；状态不明占用名额，不自动重发提交请求。
- Android 原生 dataSync 前台服务执行上传、提交、查询，展示持续通知；遵守系统超时、停止后保留日志。
- iOS background URLSession 文件上传与提交，BGAppRefresh 机会性查询，前台自动对账。
- 全局任务数量、任务中心、录音列表/详情状态、真实上传进度、待上传取消。已提交任务继续在云端执行。
- 系统本地完成提醒；拒绝通知授权不阻塞执行。通知不含录音标题或正文。
- 原生结果持久保存，既有转写版本写入完成后确认清理；崩溃窗口恢复不重复生成版本。
- 账号与 Key 范围隔离，切换范围停止旧任务的网络调度，恢复原范围可继续同步。
- 原生任务日志不存储 Key；使用独立 Keychain / Android Keystore 保护任务凭据。日志损坏时拒绝重放同一任务。

## 本轮验证

- `flutter analyze --no-pub`：无问题。
- `flutter test --no-pub`：67 项通过，其中新增 7 项后台桥接、持久化恢复、结果确认失败、范围隔离与取消测试。
- Android API 34 模拟器新增原生流程通过：真实二进制 HTTP 上传、单上传/双云端、排队取消、停止 Dart 轮询后原生继续调度、返回同步、提交 500 不重复重发、Key 不进入任务快照。
- iOS 26.5 模拟器新增原生流程通过：background URLSession 上传/提交、相同队列上限、取消、暂停前台轮询后返回同步、提交不明不重放及范围隐藏。
- 本地 HTTP 对端与音频、Key、转写结果均为合成数据，没有调用收费 AssemblyAI。测试地址只在原生 Debug 构建允许 loopback；Release 仅使用官方 HTTPS 地址。
- 此前已通过 164 组协议、14 项存储和 6 组 Web 转写契约基线；本轮未重复运行这些脚本，改动不涉及协议和音频恢复。

## 明确边界

iOS 的后台刷新由系统决定时间；用户强制退出、关闭后台刷新、低电量或网络变化可能延迟查询和后续排队任务。已经拿到远端 ID 的转写由 AssemblyAI 执行，不依赖手机保持运行。没有伪造云端完成百分比或用音频静音循环维持进程。

本地通知只能在客户端获知完成后发送，不能代替远程推送提供即时提醒。Android 也不能保证在用户强行停止或厂商省电限制下持续执行。本轮模拟器检验了逻辑/生命周期信号和原生传输，没有据此宣称验证了真机长时间锁屏、系统杀进程、BGAppRefresh 的实际唤醒时机或 Android 15 的六小时超时。

不需要用户补充服务器或推送凭据。真实 AssemblyAI 服务、真实移动网络与长时间锁屏测试留待用户自己的 Key/设备进行，不阻碍本轮实现交付。

设计依据与系统文档见[纯客户端后台方案](phase-3-local-background.md)。
