# 长音频段落核对与全文导出

日期：2026-11-03。本轮完成两条长录音的“文本段落＋句段时间＋讲话人”候选稿、离线核对页面、全文导出，以及 30 秒切块对照实验。它是第一阶段的核对工具，尚未接入正式录音库、后台任务队列或 ChatGPT 扩展。人工准确率评分仍未完成，G0 不放行。

| 模型讲话人编号 | 12 | 9 |

段落时间均为模型候选范围；“全部具有正时长并位于音频内”不代表边界准确。疑问标记包括讲话人归属不明、可能换人、可能重叠讲话、词时间缺失较多、段内间隔较大或词跨度异常。

页面支持：

1. 切换两条长录音，点击段落时间回听；播放时可自动跟随，支持倍速与前后跳转。
2. 查看讲话人编号、累计独占讲话时间、代表片段试听；修改名称后在全文中复用。
3. 按全文关键词、讲话人、重点核对范围、有疑问或未核对状态筛选；分页避免一次渲染上千段。
4. 修改段落文字、讲话人和起止时间；修改自动写入浏览器独立校对稿，原始模型结果不变。
5. 使用者回听后可逐段标记已核对。修改文字、归属、时间或相关讲话人名称后会清除对应核对状态。
6. 下载并恢复 JSON 校对备份。备份绑定源哈希与段落版本，不能误套到另一份录音或另一版分段。
7. 导出整条录音的 Markdown / TXT，包含当前修改、讲话人、时间与核对状态。搜索和筛选不删减导出全文。

浏览器保存受当前浏览器、当前地址与存储空间影响。需要长期保留修改时应下载校对备份；服务地址和 `file://` 地址的浏览器存储彼此独立。

## 合并规则与独立检查

对齐字词按归一化后的字符与原始 ASR 文本精确顺序匹配，标点、大小写与空白保留。匹配失败时保留完整源块并标为粗时间，不跳过文字。实际两条录音均匹配成功，每个 ASR 源块的全部字符都可由段落原样重建。

按句子边界及持续换人位置分段；中文不在无标点的字间因自动讲话人变化强行断开。零时长词保持原始结果，零时长词组成的短句与邻句合并形成候选段落范围，不插值制造词级时间。词级无效比例仍然是原基准的中文约 7.8%、英文约 33.2%。

讲话人按有效词区间与整条录音 `exclusiveTurns` 的时间交集分配：领先编号的交集占比至少 70%，覆盖至少 50% 的有效词时长，否则设为待确认。该比例是合并规则，不是模型置信度或准确率。原始 `turns` 中至少 150 毫秒的不同编号重叠会单独标记。页面中的“讲话人 1”等按首次出现排序，与模型原始编号同时保留，不自动推断真实姓名或真实人数。

独立结构检查通过：所有源字符保留、段落 ID 唯一、段落范围位于原录音内、初始人工核对状态均为 false。结构检查结果在 `.local-audio/reports/long-review/structural-audit.json`。

## 30 秒切块实验

使用已固定的本机模型，在每条录音首、中、尾各选一个现有源块，再按 30 秒独立转写与对齐，共 21 个子块、约 10 分钟音频。ASR 含加载耗时 45.70 秒，对齐含加载耗时 7.55 秒；没有触及生成上限或发现重复循环。

| 同一选区内的候选结果 | 120 秒基线无效字词时间 | 30 秒独立转写与对齐无效字词时间 |
| --- | --- | --- |
| 中文，约 4.9 分钟 | 98 / 1,272，7.7% | 113 / 1,262，9.0% |
| 英文，约 5.1 分钟 | 269 / 826，32.6% | 349 / 825，42.3% |

30 秒方案没有改善这项结构指标，因此没有替换长录音基线。两个方案的转写文本也不同，该实验比较的是两套处理结果，不能把差异归因于单独的对齐参数，更不能把任一候选稿当人工真值计算准确率。安装中的 MLX 实现使用 `timestamp_segment_time=80.0` 毫秒，短词出现相同起止刻度具有实现层原因，但不能据此忽略实际定位核对。

完整结果与原始子块在 `.local-audio/experiments/windows-30s/`，`summary.json` 为紧凑结果，`results.json` 含两种候选文字与词时间。

## 验证与限制

浏览器功能检查覆盖两条录音切换、跨 40 分钟的搜索与回听跳转、文字修改后刷新恢复、人工核对标记、整条 Markdown 导出、注入文本按纯文本显示、手机宽度无横向溢出。新增段落与服务测试覆盖源时间映射、文字无损、零时长处理、未知归属、源版本不匹配及音频 Range 读取。测试结果与截图保存在本机 `.local-audio/reports/long-review-qa/`。

Node 全量 270 项测试通过，生产构建通过；Python 35 项测试通过。最终两条录音的浏览器导出逻辑与预生成 Markdown / TXT 全文逐字符一致，源文字重建、唯一段落 ID、初始核对状态与时间范围的独立检查也通过。

目前没有经过独立回听建立的全文参考、人物真值或时间锚点。因此不能报告 CER/WER、DER 或时间偏差达标。句段候选稿的用途是让使用者能够核对，不意味着模型精度问题已经解决。

## ChatGPT 网页与跨聊天验证

本轮通过已登录的 Edge / ChatGPT 原生上传入口上传英文 `en-long.transcript.md`，没有使用 OpenAI 开发者 API。上传文件 140,706 字节，SHA-256 为 `ae180d445e6af4355edb64de0cbd64a9da90e40a6387d079bb4890117869f164`。

1. 在上传文件的聊天中询问约 10、40、70 分钟的内容。返回了三处内容、讲话人标签及来源范围，已与本地候选稿逐项核对一致。
2. 打开独立新聊天，不重新附加文件，只给出文件名，要求检索约 20、60 分钟内容。ChatGPT 通过资料库（Library）取得稿件，返回文件大小及 982 段元信息，并引用新的原文和来源范围。
3. 新聊天中的 `00:20:02.080–00:20:37.120`（讲话人 2）、`01:00:04.800–01:00:11.760`（讲话人 6）及补充的 `01:00:57.760–01:01:01.280`（讲话人 2）均与本地对应段落的文字、标签和范围匹配。

实验记录在 `.local-audio/experiments/chatgpt-transcript-validation.json`。这次证明英文候选全文可以通过当前账号的资料库跨独立聊天检索并引用；未创建原生 Page 或独立 Space，也不代表任何未来聊天都会默认自动引用。使用时明确提供文件名并要求检索更便于核对。

两次测试均要求不更新 Memory；没有将全文或音频写入 Memory。检索成功验证的是候选文本的复用，不是重新听辨音频后的准确率。中文稿本轮完成本机核对与导出，网页检索实验使用英文稿。

## 重建与启动

从工程根目录执行：

```sh
PYTHONPATH=worker worker/.venv/bin/python -m recdock_audio.long_review \
  --root .local-audio/benchmarks \
  --source-dir "$HOME/Downloads/audiobridge素材/音频测试" \
  --output .local-audio/reports/long-review

PYTHONPATH=worker worker/.venv/bin/python -m recdock_audio.review_server \
  --root .local-audio/reports/long-review --port 8766
```

服务仅监听 `127.0.0.1`，只读指定核对目录，支持字节 Range 以跳转长音频，不提供文件写入或目录列表。
