# App 第一阶段：登录、设备读取与录音播放

更新时间：2026-11-07。目标平台：Android、iOS。第一阶段功能已实现，双端模拟器完整流程已通过；验证证据与范围以[交付记录](phase-1-delivery.md)为准。本轮使用模拟器验收，物理 BLE 与真实云端账号现场联调留作后续集成记录。

## 用户确认与范围

用户确认 Web 的真实设备完整链路已经验收，当前转写质量符合预期；后续优化不阻碍 App 开发。App 沿用 Flutter 双端工程，新增差异为：转写优先接入 **AssemblyAI 云端服务**，手机内本地大模型不作为首版建设方向。

**第一阶段交付目标：使用已有 PLAUD 账号登录，连接该账号已经绑定的实际设备，读取真实状态和录音目录，把设备录音下载到手机后正常播放。** 本阶段账号指 PLAUD 账号，不新增 RecDock 自建账号系统。

当前已接入录音工作台、本机导入/播放、持久化/去重、搜索/改名/回收站、扫描、账号登录/恢复、GATT、传统/协议 20 认证、状态/目录、流式下载、原件解密和播放副本。模拟器播放验收使用合成的加密 PLAUD.AI / Opus 录音链路，不以普通 MP3/WAV 导入替代。

第一阶段不加入 AssemblyAI 实际上传/计费、转写校对、ChatGPT 自动发送、实时字幕、新设备绑定/解绑、设备录音控制、设备文件删除、OTA 或 Wi-Fi 传输。首个兼容目标为用户已经在 Web 验收的设备和固件；不为支持更多型号推迟该目标交付。

| B：账号与绑定设备 | P0-03 PLAUD 云端客户端迁移 | 现有 Web 登录实现 | 手机直接完成官方区域路由、账号登录、账号信息和绑定设备列表；不依赖运行中的 Web 或 Mac 服务 |
| B | P0-04 安全存储与会话生命周期 | P0-03 | 重启恢复登录、token 刷新、退出与账号切换；密码不落盘、凭据使用系统安全存储 |

| C：连接与状态 | P0-06 GATT 传输层 | P0-01；现有扫描 | 服务/特征发现、通知订阅、串行写入、通知收件队列、超时、取消与断连清理在两端工作 |
| C | P0-07 BLE 认证与会话加密 | P0-05、P0-06 | 迁移目标设备所需的 token/RSA 握手和加密报文；认证后实际状态请求成功才显示连接可用 |
| C | P0-08 状态、录音事件与目录 | P0-07 | 显示真实电量/充电、存储、录音状态与目录；刷新、推送、断线后的状态正确 |
| D：下载到播放 | P0-09 下载状态机与完整性 | P0-08 | 选择文件、进度、取消、断线后同次运行内继续；按连续偏移与声明长度校验，不把未完成文件当完成 |
| D | P0-10 设备文件恢复与本机入库 | P0-09、P0-02、P0-04 | 解密支持格式、Ogg 封装/校验、保留原件和播放副本；按账号/设备/文件标识隔离与去重 |

实施先后为 **A → B → C → D → E**。P0-01 工具链处理、P0-02 解码验证和不依赖手机环境的协议/账号迁移可以交错推进；状态、目录和下载按其依赖接入，不把阶段末尾当作首次手机联调。

批次 B 结束即可演示“登录和绑定设备列表”，批次 C 结束即可演示“连接和状态/目录”，批次 D 结束即可演示“设备录音下载播放”。

## 关键实施内容

### P0-01 / P0-02：尽早证明两端可以运行和播放

原生构建环境已打通，40 项 Flutter 测试、164 组协议对照和 14 项存储检查通过；Android API 34 与 iOS 26.5 模拟器均完成原生安全存储和设备录音播放链路。早期 Gradle 缓存写入、iOS 引擎和 CocoaPods 问题已解决，保留系统凭据保护，不以明文存储规避环境问题。

以设备真实音频的格式、声道和容器作为解码验证输入。Android/iOS 都要实测，不能只用 MP3/WAV 本机导入或容器解析成功作为设备播放结论。若当前播放器不能解码目标 Opus/Ogg，补移动端解码与按需生成播放副本，优先验证这条路线；转换不改变原件，长音频不全量加载到内存，不默认生成整条巨大的 PCM 文件。

### P0-03 / P0-04：账号与凭据

迁移依据：`plaud-web/server/cloud-client.ts`，而不是仅迁移调用 Web 本地 `/api/` 的前端封装。

- 邮箱密码登录、官方区域识别、账号信息、绑定设备列表和明确的错误提示；兼容已有密码加密/响应解码规则。
- 登录失败不写入半成品会话；重启校验账号身份，支持的登录态自动刷新；并发刷新合并，token 对原子保存。
- 账号令牌和 RSA 材料按账号隔离，使用 iOS Keychain / Android Keystore 保护的安全存储。密码仅用于本次登录；日志与错误不输出 token、私钥或原始密码。
- 普通退出清除登录授权与当前连接，保留本机文件；账号录音在未授权时隐藏，本机导入仍可用。对应账号重新登录后恢复其录音可见性。
- 历史录音解密材料与普通登录授权分别管理；账号切换不复用上一账号的设备凭据、下载缓冲或私有录音范围。

首个演示以普通账号登录为主。官方 Web 会话手工导入可作为后续兼容入口，不取代 App 自身登录能力。

### P0-05～P0-07：真正的设备连接

迁移依据：Web `src/auth/credentials.ts`、`handshake.ts`、`session.ts`、`src/ble/` 与 `src/app/controller.ts`。

- 广播用于发现与取得协议信息；云端列表用于确认账号绑定关系，两者按实际 SN 对齐。设备名称、MAC/系统 UUID 不代替 SN 或账号授权。
- 已支持协议范围以目标设备实际需要为准，复用 Web 的传统协议 / 协议 20 能力。协议 30 自动准备仍是独立扩展，不把 Web 原本不具备的能力写成 App 已支持。
- 获取 SN 签名、按需取得并复用账号 RSA 材料；区分登录 token、账号 ID / BLE token、工作区授权与会话密钥。
- 服务 `1910`、RX `2bb0`、TX `2bb1` 的发现和实际特征能力检查；先订阅通知，再按设备要求写入握手。GATT write 完成不等于设备认证成功。
- 握手分片、返回 SN/协议校验、解密校验、业务包序号与重放处理通过 Web/Dart 相同材料对照验证；不改设备既定线缆格式。
- 区分未连接、连接中、认证中、可读取、断开与失败。退出、切换设备、取消连接使旧异步响应失效，关闭界面不会留下悬挂命令或串台状态。

### P0-08：状态和录音目录

- 读取设备状态、电量/充电、可用/总存储，接入录音开始/暂停/恢复/结束和时长推送；仅监听，不新增录音控制功能。
- 缺失信息显示未知，电量 0% 正常显示；断连清除实时状态，旧数据不冒充最新状态。
- 迁移分页/分包目录聚合、请求 ID、条目总数/索引与重复/缺口校验，避免只显示第一包。
- 文件保留实际 sessionId、大小、属性等；合理时间戳按手机时区显示日期，自定义名称和身份编号分离。
- 明确区分“账号已绑定设备”“附近设备”“已经认证可读取设备”“设备上的待下载文件”“已保存到本机文件”。

### P0-09～P0-11：下载、恢复和播放

迁移依据：Web `src/app/file-transfer.ts`、`src/audio/plaud.ts`、`ogg.ts`、`recovery.ts` 与现有 App `recording_store.dart`。

- 一次一个设备传输，按顺序写入临时文件，显示实际字节进度；先验证源文件大小和本机可用空间，避免沿用 Web 的整条录音内存缓冲。
- 处理确认包、连续偏移、重复重叠数据、内容冲突、缺口、结束原因、超时和取消后的停止确认；不把发送停止命令本身当作设备已停止。
- 取消/断线后，在同次 App 运行内对同账号、同设备、同 session 和相同源大小允许继续。跨 App 重启的持久续传是后续增强；已完成录音重启后持续可用。
- 设备正在录音或暂停时暂缓文件同步，下载中进入录音状态则按设备协议暂停；不主动终止用户录音。
- 解开支持的 `PLAUD.AI` 原件和对应内容密钥，恢复 Opus/Ogg；保留原始文件。缺少正确历史密钥或未知格式明确失败，不能仅改扩展名生成“可播放”状态。
- 按已知规则验证声明长度、偏移和容器完整性；原始文件尾 CRC 字段保留，未确认算法不宣称已经校验。Ogg 页 CRC 按 Web 已有实现验证。
- 现有 App 个人库索引升级：增加来源、账号范围、设备 SN/标识、sessionId、原始与可播放资产及哈希；旧本机导入继续归个人库。入库成功后才把设备列表条目标记为已下载。
- 下载后定位录音详情，支持播放/暂停、进度拖动与时长显示；已有完整文件复用，不因重复点击再下载。断开设备或网络后，已完成录音仍能播放。
- 第一阶段提供前台下载与前台播放。离开前台时明确暂停/中断状态并保留已接收部分，不承诺系统挂起或杀进程后的持续传输/播放。后台播放和后台下载另行安排。

## 第一阶段验收场景

1. 使用已有 PLAUD 账号在 Android 与 iOS 真机分别登录，列表展示该账号实际绑定设备；重启恢复，退出/切换不串账号。
2. 手机在附近发现目标设备，连接并认证成功后显示真实电量、存储和录音状态；关闭蓝牙、设备休眠或断线后状态准确变化。
3. 刷新得到设备完整录音目录；设备增加录音后可刷新看到，文件大小、编号和已下载状态一致。
4. 下载一条真实录音，观察进度与完成状态；原件和播放副本均保存，Android/iOS 均可听到正确内容并跳转播放。
5. 断开 BLE、关闭网络、重启 App 后，已经完整保存的录音仍可读取和播放。
6. 验证错误密码/登录失效、权限拒绝后恢复、SN 不匹配、设备被占用、取消下载、缺包/重复包、断线重连、空间不足、解密失败等；不误报连接或下载成功，不丢原件。
7. 上述流程不调用 AssemblyAI，不隐式上传录音；无需运行 Web、Mac 本地服务或本地模型。

Web 既有验收继续有效；此处验证的是新增的 Android/iOS 实现，不重新打开 Web 转写质量验收。

## 第二阶段：AssemblyAI 转写与结果查看

实施状态：P1-01～P1-05 已实现，个人内测采用自带 Key；当前验证结论、使用方式与范围见[第二阶段交付](phase-2-delivery.md)。以下保留原任务定义。

第一阶段完成后接入异步录音转写：**用户主动选择转写 → 上传完整可解码音频 → 创建任务 → 查询状态/恢复任务 → 保存全文 → 查看说话人与时间并回听。**

| 任务 | 工作内容 | 验收结果 |
| --- | --- | --- |
| P1-01 接入与密钥方案 | 配置提供方、凭据归属、服务区域和费用承担；个人内测的自带 Key 与面向用户的服务端代理方案在接入时确定 | 不把产品共享长期 Key 打包进 App；凭据和账号授权隔离 |
| P1-02 上传与提交 | 上传完整的可解码副本，创建转写任务，记录本机录音 ID / 源哈希与远端任务 ID | 明确由用户发起，显示上传进度；重复点击不重复创建本机任务，提交结果未知时不盲目重发 |
| P1-03 异步任务恢复 | 处理 queued / processing / completed / error、断网、限流与重启恢复 | 持久化任务 ID，网络恢复后继续查询；不把 App 停止轮询等同于取消服务端任务或费用 |
| P1-04 结果适配与回听 | 适配全文、说话人、句段/词时间与 provider 信息到 App/共享契约 | 时间统一为原音频毫秒；保留提供方来源，缺失信息不伪造；文字段落可回听 |
| P1-05 校对与导出 | 标题、人物名称、文字校对、历史版本、全文导出与系统分享 | 沿用 Web 的已保存完整版本原则，不因搜索/分页截断；手机 ChatGPT 交接后续按实际入口接入 |

已核对官方文档：文件使用 `/v2/upload` 上传并获得 `upload_url`，通过 `/v2/transcript` 创建异步任务，再使用任务 ID 查询状态；说话人区分返回 `utterances` 与词时间。模型、语言、费用和区域在实际接入时核对并配置，本轮不固定价格、不执行上传或付费调用。[上传接口](https://www.assemblyai.com/docs/pre-recorded-audio/api-reference/files/upload)、[提交转写](https://www.assemblyai.com/docs/pre-recorded-audio/api-reference/transcripts/submit)、[状态与查询](https://www.assemblyai.com/docs/pre-recorded-audio/check-transcript-status)、[说话人区分](https://www.assemblyai.com/docs/pre-recorded-audio/label-speakers)。

AssemblyAI 的上传 URL 用于其转写处理，不作为 App 音频播放地址或本机录音唯一副本；App 播放继续读取本机资产。[官方上传 URL 说明](https://www.assemblyai.com/docs/faq/why-cant-i-access-urls-from-the-upload-endpoint-directly)。
