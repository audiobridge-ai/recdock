# RecDock 桌面产品与开源展示方案

日期：2026-11-12。用途：统一后续产品、工程、开源发布和能力展示的实施方向。

执行补充：用户随后明确暂不购买开发者认证，本轮先交付可手动允许打开的发布候选包。因此下面关于 Developer ID、公证与干净 Mac 的正式分发要求保留为后续目标，不作为本轮候选包的已完成事项。当前候选版实施与真实检查见[验收进度](reports/desktop-rc-progress-2026-11-12.md)。

RecDock 定位为开源、免费、本地优先的录音工作台。先交付可以独立使用的 Mac App，再根据实际需求推进 Windows App；官网承担产品介绍、软件下载、案例展示和合作联系。项目的主要回报是让设备厂商和行业客户看见完整交付能力，并促成技术交流与合作。

用户已认可现有模型质量。Mac 版保持当前模型、固定修订和处理流程，不因界面迁移或下载体积改用其他模型。本方案规定后续目标；目前已交付的是 Mac 本地助手与在线工作台，尚未完成独立桌面工作台和公开分发。

## 产品定位与展示目标

对使用者，RecDock 解决“取出录音、转成可回听和校对的文字、导出继续使用”的完整流程。没有 PLAUD 设备的人也可以导入已有音频使用，方便厂商和开发者直接体验。

对潜在合作方，展示重点是设备接入、协议处理、音频恢复、本地模型部署、持久任务、文字与音频联动，以及桌面软件交付。这些属于 RecDock 的工程整合能力；模型名称、来源和许可明确标注，不将上游模型能力表述为自研模型。

首批接触对象为录音设备厂商、会议和采访工具团队，以及需要本地音频处理的行业软件团队。官网提供“下载体验”“查看源码”“技术合作”三个入口，合作方向围绕设备适配、产品集成、私有化运行和桌面客户端交付展开。

## 产品组成与边界

| 组成 | 职责 | 推进顺序 |
| --- | --- | --- |
| Mac App | PLAUD 连接与录音下载、本机音频导入、录音库、本地转写、对齐、说话人区分、回听、校对、导出和一键发送到 ChatGPT | 主线，首发 Apple Silicon |
| Windows App | 共用主要界面和业务契约，适配 Windows 设备连接、运行时、推理与安装升级 | Mac 公开预览稳定后单独验证 |
| 官网 | 介绍、真实演示、系统要求、下载、安装帮助、源码入口与合作联系 | 随 Mac 公开预览发布 |
| 网页设备工具 | 在支持的浏览器中提供基础 PLAUD 连接与录音导出 | 可选后续项目，先验证能否脱离本地服务 |
| 现有 Android 和 iOS 工程 | 保留现有代码、说明和已验证能力 | 本轮不扩大开发范围 |

桌面 App 的设备操作、录音库、转写、回听、校对和文件导出在本机窗口内完成，不依赖公网工作台、浏览器扩展、网页配对码或网站授权。一键发送到 ChatGPT 继续通过浏览器扩展连接用户已登录的 ChatGPT 标签页。原有在线预览在迁移验收期间保留，之后官网与工作台分开维护，不覆盖原有 `audio-bridge` 应用。

产品初期不建设付费订阅、商业账号体系、云端录音同步和多租户管理。实时字幕、跨录音声纹身份、内置新摘要模型及自动向第三方发送全文，均不纳入 Mac 首版。

## Mac 首版使用流程

1. 用户从官网进入 GitHub Releases 下载并安装 App，首次打开看到系统与磁盘检查。
2. 在 App 中下载固定版本模型，或选择已有模型目录；显示容量、进度、许可入口、失败重试和校验结果。
3. 用户可以直接导入本机音频；连接 PLAUD 时才进入设备和官方账号相关流程。
4. 设备录音支持用户选择“仅下载”或“下载并转写”。本机导入后同样可以自主开始处理。
5. 任务页显示排队和处理阶段，支持取消、失败重试及中断后恢复；保留完整原录音。
6. 完成后显示全文、说话人和时间，点击文字回听，可以修改文字和说话人名称，机器稿与人工校对版本分开保存。
7. 导出全文和字幕，或点击“一键发送到 ChatGPT”，将当前已保存版本的完整 Markdown 转写与提示词送入已连接的浏览器标签页，提交成功后打开对应对话。发送入口明确展示外发范围，用户可以预览；不上传原始音频。

主窗口提供录音库、设备、任务和设置。关闭窗口后任务继续，菜单栏可查看状态并重新打开；明确退出 App 后停止处理，重开时恢复未完成任务。睡眠期间不承诺继续计算，需验证唤醒后的任务恢复。

无需注册 RecDock 账号即可导入、转写和导出。模型下载、首次模型许可和 PLAUD 官方账号认证可能需要联网；模型准备完成后的本机音频处理应支持离线运行。

## 一键发送到 ChatGPT

保留现有已验收功能，并将桌面端接入列为 Mac 首版验收项。现有实现通过 Edge 扩展操作用户已登录的 ChatGPT 页面，发送全文文件和提示词，核对附件、用户消息及对话链接；它依赖工作台页面与扩展之间的消息通道，迁移到桌面后需新增通信桥接，不能仅把网页放进桌面窗口就视为完成。[既有交付与验收记录](../plaud-web/docs/chatgpt-forward-delivery.md)

桌面适配优先采用 Native Messaging：浏览器扩展建立到 App 配套通信程序的连接，读取用户在 App 中发起的发送任务，并返回进度与提交回执。先支持已完成真实验收的 Edge，再验证 Chrome；后续 Windows 使用相同通信契约和各平台的通信程序注册方式。App 的录音处理不依赖这条连接，只有发送到 ChatGPT 时才需要浏览器和扩展就绪。[Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)、[Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)

首次使用由用户安装扩展、打开并登录 ChatGPT、选择连接的标签页，App 提供安装与连接状态检查。之后在录音详情点击发送，不需要重新打开公网工作台，也不为这条流程引入 OpenAI API Key。扩展发布和通信程序的安装注册属于这一功能的公开交付内容；当前扩展尚未具备桌面通信能力。

继续沿用完整稿件、修订编号、内容和提示词哈希、发送状态及结果链接。当前自动发送上限为 8 MiB，不因搜索、筛选或分页截断正文。Native Messaging 从通信程序发往扩展的单条消息限制为 1 MB，因此全文需分块传输、限制消息大小、核对完整长度和哈希后再组装，不能把 8 MiB 全文直接塞入单条消息或悄悄截断。

界面保留准备、上传、提交、已提交和需要用户处理等状态。保护用户已有草稿和附件；提交结果未知时只核对状态，不自动重发。已经确认提交的同一稿件与提示词再次点击时打开原对话。未保存编辑先保存，发送失败时提供完整 Markdown 导出作为备用路径。

桌面验收需覆盖连续发送两份稿件、重复点击、人工校对后的版本、长文件分块、App 和浏览器重启后状态核对、目标标签页关闭、已有草稿、上传失败及未知提交结果。成功条件是观察到实际附件、对应用户消息及有效对话链接，并能从 App 打开该对话。延续现有“同一已连接标签页新建对话”的行为；该操作不等于已保存到 ChatGPT 资料空间或 Memory。ChatGPT 页面变化和账号配额会影响执行，失败时保留本地资料与可核对状态。

## 模型与资源策略

| 用途 | Mac 固定模型 | 固定修订 | 当前文件总量约值 |
| --- | --- | --- | --- |
| 转写 | `mlx-community/Qwen3-ASR-1.7B-8bit` | `a8379a2e2f9e313c9292cdf1af4055ab56d50d55` | 2.47 GB |
| 时间对齐 | `mlx-community/Qwen3-ForcedAligner-0.6B-8bit` | `0e1a68e91d815300c7c9754b2a7639378b23db15` | 1.28 GB |
| 说话人区分 | `pyannote/speaker-diarization-community-1` | `3533c8cf8e369892e6b79ff1bf80f7b0286a54ee` | 34 MB |

模型共约 3.78 GB。当前助手 ZIP 为 361,576,171 字节，约 362 MB；因此当前组合首次下载约 4.14 GB，展开后 App 与模型约占 5 GB。建议至少预留 10 GB，并为录音、解码临时文件和升级额外留空间。这里使用十进制 GB 和 MB。

这些容量来自当前助手与本机模型文件；Electron 桌面版加入 Chromium 后，安装包和运行内存需要重新测量，并以实际发布结果更新官网，不将当前助手容量作为未来版本承诺。

模型独立于应用安装包和应用升级。保留固定修订、文件哈希、已有目录校验及离线目录导入；补齐可恢复下载、磁盘不足提示和失败处理。更新应用不重新下载未变更的模型。新处理任务记录模型版本和处理参数，便于复现。

pyannote 目前需要用户接受模型访问条件，App 继续提供官方授权入口和本机令牌保存，不共享项目维护者的令牌。[模型官方访问说明](https://huggingface.co/pyannote/speaker-diarization-community-1)

已接受的模型选择保持不变。用既有录音与结果建立迁移回归样本，重点防止切段、对齐、说话人编号和导出发生退化；后续若调整模型、修订、量化方式或关键处理参数，需明确记录并使用同一批录音对比。

## 桌面工程路线

采用 Electron 桌面界面、共享 TypeScript 业务代码、独立本地服务和 Python Worker。选择依据是现有工作台已经包含主要交互和蓝牙协议实现，Mac 与 Windows 可以共用界面、录音数据契约和任务逻辑。Electron 提供 Web Bluetooth 接入及设备选择事件，但现有 PLAUD 设备仍需完成桌面端真机验证。[Electron 设备接口](https://www.electronjs.org/docs/latest/tutorial/devices)

| 层次 | 实施方式 |
| --- | --- |
| 桌面界面 | 将现有工作台构建结果随 App 打包；适配桌面窗口、菜单、拖入文件和快捷键，不在主窗口加载在线工作台 |
| 应用管理 | 管理窗口、菜单栏、权限、文件选择、进程启动退出、系统通知及更新检查 |
| 设备连接 | 先复用现有蓝牙协议与传输代码，接入明确的设备选择界面；广播和认证缺失能力通过平台适配补齐 |
| 本地服务 | 复用当前 Node 录音库、账号材料管理、队列、修订、媒体和导出；迁移初期保留已经验证的独立 Node 运行时 |
| 处理 Worker | 继续使用现有 Python、MLX、pyannote、FFmpeg 流程，保持后台任务独立于界面 |
| 平台适配 | 隔离密钥保存、蓝牙广播、进程锁、数据目录、推理后端、签名和安装流程 |

桌面内部通过受限桥接和本次启动的内部凭据连接服务，保留访问控制和单实例锁。界面使用上下文隔离，关闭 Node 直接访问，只暴露必要接口；官网、文档和第三方登录页面在系统浏览器中打开。[Electron 安全指导](https://www.electronjs.org/docs/latest/tutorial/security)

现有 `companion-macos` 保留为已验证的历史实现，复用它的运行时打包、资料路径、进程管理与模型准备经验。逐步引入共用桌面入口，不在首次迁移时大规模改名或移动整个仓库。桌面版继续读取既有 RecDock 资料与模型配置；升级前保留备份，禁止旧助手与新版同时写同一录音库。

首版更新采用“检查版本、查看更新说明、打开对应下载页、安装替换”。资料与模型保存在应用包之外。静默更新和差分更新等后续确有需要时再推进。

## Windows 推进方式

Windows 版在 Mac 完整流程稳定后实施。界面与业务复用，推理运行时单独验证；保持 Qwen3 ASR 1.7B、ForcedAligner 0.6B 和当前 pyannote 的模型方向，优先评估相同上游固定修订的可用权重。Mac 的 MLX 文件不能直接作为已经通过 Windows 验收的产物。

先验证 NVIDIA CUDA 路径，再实测 CPU 的可用性。AMD、Intel GPU 和 Windows ARM 支持以实际结果决定，不在首轮宣传中承诺。Qwen 官方提供 Transformers 等运行后端，但目标 Windows 环境的兼容性、部署包、内存和速度仍属于本项目需要完成的验证。[Qwen 官方实现](https://github.com/QwenLM/Qwen3-ASR)

使用同一批中文、英文、中英混合和多人长录音比较两平台的正文、时间定位和说话人结果。任何权重转换或量化差异都需要对比记录；不以模型名称相同推导输出质量已经等价，也不通过更换较小模型默认满足兼容性。

## 开源与安装包发布

使用现有 GitHub 源码仓库，项目自有代码继续采用已有 MIT 许可证。提供清晰的 README、架构和平台适配说明、可复现构建入口、依赖锁、贡献说明及问题反馈入口。第三方模型、运行时和 FFmpeg 依赖按各自许可保留声明，完成当前嵌入组件的分发和对应源码要求。

公开前检查待发布文件和 Git 历史，排除个人录音、账号缓存、令牌和签名材料。演示录音使用可公开的材料；现有真实会议录音不自动成为宣传素材。

安装包直接发布到同仓库 GitHub Releases，官网按钮指向版本附件。GitHub 当前要求单个附件小于 2 GiB，适合当前体积的 App 安装包；模型保持独立下载。[GitHub Releases 官方限制](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)

每次发布包含版本更新说明、系统和芯片要求、已知问题、安装包、SHA-256 校验值及第三方说明。Mac 优先提供 DMG，按需同时提供 ZIP；Windows 后续提供对应安装包。预览版与稳定版明确区分，安装包可追溯到源码标签、依赖与构建记录。

Mac 公开版使用自有或明确获授权的 Developer ID 签名，完成公证、附加公证票据和实际下载后启动验证。当前 ad-hoc 包继续用于本地测试。发布时以签名、打包后的真实文件计算校验值，再上传 Release。[Apple 分发说明](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution)

Mac 首发 Apple Silicon。当前助手仅验证 macOS 26.2 及以上，需处理 FFmpeg 等依赖的系统版本限制；旧系统的支持范围根据实际构建和干净机器测试确定。Intel Mac 支持单独评估，不随 Apple Silicon 版默认宣布。

## 官网与能力展示

官网继续使用独立 Vercel 项目。公开站点提供产品介绍、2 到 3 分钟真实操作视频、界面截图、支持范围、版本与下载、模型容量、安装帮助、源码入口和技术合作联系。一键发送到 ChatGPT 的介绍同时标明浏览器扩展要求。Windows 未发布时明确标记准备状态，不提供不可用的下载按钮。

演示应展示安装后的实际操作：导入或设备下载、任务执行、查看全文、时间回听、校对、导出和一键发送到 ChatGPT。若等待过程被剪辑，标注实际处理耗时与测试机器。提供可公开的短样本及输出，方便他人复现；性能结果同时标注音频长度、硬件、模型版本和测量方式。

合作介绍围绕设备接入、本地音频处理、已有产品集成和桌面交付展开，以工作邮箱或明确的联系方式承接咨询。README 与官网呈现统一身份、能力范围和联系入口。RecDock 保持独立产品定位，不暗示获得 PLAUD 官方背书。

网页设备工具后续单独决策。须在未安装 App 的机器验证官方账号认证、协议版本获取、录音下载和解密全流程；若依赖仍存在，继续引导使用 App，不在官网宣称已提供纯网页完整导出。

## 阶段与验收

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| 第一阶段 独立 Mac 工作台 | 桌面主窗口、设备连接、本机导入、任务与转写编辑、本地数据沿用、ChatGPT 扩展通信桥接 | 从 App 完成导入或设备下载、真实转写、回听、校对、导出及一键发送到 ChatGPT；本地流程无需终端或公网工作台，窗口关闭、退出重开和任务恢复通过；ChatGPT 实际附件、用户消息与对话回执通过 |
| 第二阶段 安装与首次使用 | 模型准备、安装包、兼容性结果、升级与资料保护 | 在另一台无开发环境的 Mac 完成首次安装、模型下载与许可、真实处理；验证离线处理、磁盘不足、取消、失败恢复与升级保留资料；确定实际系统范围 |
| 第三阶段 开源公开预览 | 可构建源码、经签名公证的 Release、ChatGPT 扩展安装入口、公开官网、演示与样本 | 从官网下载正式附件后正常安装启动，校验值匹配；外部使用者能按文档完成本地处理及扩展安装连接与发送；模型与第三方声明完整 |
| 第四阶段 试用与合作反馈 | 试用问题记录、改进版本和厂商需求摘要 | 目标邀请 5 到 8 位真实使用者，其中争取 2 到 3 位来自相关厂商；记录安装与使用阻碍、集成诉求和后续沟通，数字为试用目标 |
| 第五阶段 Windows 预览 | Windows 运行时、设备适配与安装包、跨平台质量对比 | 在明确支持的 Windows 硬件完成相同核心流程和质量对比，再发布支持范围 |

第一阶段先做小范围端到端验证，重点确认桌面中的设备连接、既有模型真实推理、界面关闭后任务继续，再扩展完整界面。现有模型质量认可继续有效，验证重点是迁移不退化；长录音仍需覆盖既有约 80 到 100 分钟的真实使用场景，并实测耗时、内存和时间定位。

工程按阶段验收推进，当前不承诺未经验证的开发工期、最低内存或处理速度。签名账号准备可与功能开发并行，公开分发以第三阶段的真实下载验收为准。

## 成效观察与投入顺序

主要观察有效厂商咨询、具体设备或集成需求、技术交流及试点机会。下载量、Star 和 Issue 是辅助信号；同时跟踪试用者能否完成首次模型准备和首条音频处理，以及最常见的失败原因。默认不收集录音或全文，问题反馈由用户主动提交必要诊断信息。

投入优先级为核心流程可靠性、首次使用、真实演示、源码可读性和合作联系。Windows 和网页设备工具根据反馈继续投入。应用保持免费和开源，不为产品直收费增加登录、支付和运营系统。
