# RecDock App 双端开发

## 已确认的产品基线

用户已确认 plaud-web 的真实设备完整链路验收通过，转写质量符合当前预期，并指定 Android 和 iOS 双端。Web 作为首版能力迁移的参考基线，质量按后续用户反馈迭代，不重复设置 Web 质量开工门槛。[Web 验收记录](../../plaud-web/docs/reports/feature-readiness-2026-11-07.md)保留用户确认与自动化证据。

用户进一步确定：App 后续接入 **AssemblyAI 云端转写**；第一阶段先完成 **PLAUD 账号登录、已绑定设备连接、真实状态和录音目录读取、下载及本机播放**。详细任务、依赖与验收以[第一阶段任务计划](phase-1-device-playback.md)为准。手机内本地大模型与云端转写接入均不作为第一阶段的前置条件。

采用 Flutter 共享界面、领域逻辑、状态与协议编解码，Android/iOS 插件承担蓝牙、文件选择、沙盒目录和音频播放。此选择用于独立 RecDock App，不改变现有 plaud-web 技术栈。

## 模块边界

- `lib/core/protocol/`：从 Web 移植的广播、报文整数、目录/下载帧和状态编解码，不调用平台插件。
- `lib/features/library/recording_store.dart`：个人本机录音库，SHA-256 去重、串行变更、原件与索引原子发布、标题、软删除/恢复。导入不会隐式转写。
- `lib/features/devices/device_scanner.dart`：显式触发系统权限和前台扫描；停止、超时和 App 离开前台时取消；根据真实厂商广播和 SN 识别设备。
- `lib/app.dart`：录音、设备、设置与详情播放；不依赖 PLAUD 账号才能使用本机录音。
- `android/`、`ios/`：原生工程、Bluetooth 权限和平台桥接。已加入原生后台转写上传与任务调度；设备下载和播放仍限前台，没有录音麦克风权限。
- `test/`：协议、存储与页面测试；`tool/` 提供不监听端口的跨语言协议和存储校验。

录音保存在 `getApplicationSupportDirectory()/library-v1/rec_<id>/`。个人导入保留 `source.<扩展名>`；设备录音保存 `source.bin`、可选 `audio.ogg` 与 v2 `recording.json`，保留源 SHA-256 和账号/设备/session 范围，iOS 按需生成 CAF 缓存。兼容原 v1 个人库，不包含 Web 录音库批量导入。回收站不释放空间；卸载会清除沙盒音频，备份/分享能力后续补齐。

## 手机适配约束

Web 的广播厂商数据已经剥离公司标识，而移动 BLE 插件包含该标识；App 在解析前校验并移除两个字节，已有对应回归。名称和信号强度不作为认证依据。扫描只证明发现设备，M2 的 GATT、密钥和 token 握手完成后才能标记连接成功。

移动转写执行与领域契约分离，已接入用户指定的 AssemblyAI。个人内测采用自带 Key，按当前账号范围保存到系统安全存储；没有服务端共享 Key。用户主动确认上传，原件保留，远端 ID 可恢复；不自动重提收费请求。具体行为和真实服务联调边界见[第二阶段交付](phase-2-delivery.md)，不依赖 Web 的 Node/Python/MLX 服务、macOS 广播辅助或 Edge 扩展。

设备解密与 Ogg/Opus 恢复已接入，Android 原生播放 Ogg/Opus，iOS 流式生成 CAF/Opus 缓存后播放；原件始终保留，未知格式明确提示。个人导入仍使用平台支持的格式。

新设备绑定/解绑、设备录音控制、设备文件删除、OTA 和 Wi-Fi 传输沿用 Web 的范围边界，后续按明确需求加入。
